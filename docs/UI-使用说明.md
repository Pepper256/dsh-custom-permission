# dsh-custom-permission：Web 界面（GUI）使用说明

本文面向使用 Web 面板管理权限预设的用户：如何打开面板、新建预设、编辑与删除，以及**编辑器里每个输入框到底是什么、该怎么填**。配置概念与字段总览见根目录 [`README.md`](../README.md)（"使用说明（最终用户）"一节）。

- 前提：profile 已安装本插件（见 README「安装」）。聊天输入框**右侧的 ⚙ 按钮**即入口；若升级插件后看不到新功能，先刷新页面（F5）加载最新界面。
- 术语：**预设 = 一套权限规则**，同一时刻只有一个生效（进程级，对所有会话一致）。默认预设名为 `default`。

---

## 1. 面板（⚙）里有什么

点 ⚙ 打开面板，从上到下：

1. **标题栏**：`权限预设` + 右侧 ✕（关闭面板）。
2. **预设列表**：每个预设一行——左边是名字，当前生效的会加粗并标"当前"；行内右侧两个按钮：**✎**（编辑）、**🗑**（删除）。
   - **点击预设名字 = 切换到该预设**（立即生效，不需要保存）。
3. **详情区**：当前预设（激活项）的四类权限明细：允许/拒绝规则、自动放行工具、额外可写路径。
4. **底部**：`＋ 快捷添加` —— 打开"新建预设"弹框。

> 打开面板会自动拉取一次列表；切换、新建、删除后列表自动刷新。操作出错时面板顶部或弹框内会出现红色错误提示。

---

## 2. 快捷添加（新建预设）

1. 点面板底部 **`＋ 快捷添加`**，弹出"新建预设"窗口（覆盖在聊天区上方，点弹框外空白或 ✕ 可关闭、不保存）。
2. 填 **预设名称**（见 3.1），再按需添加权限（见 3.2–3.5）。
3. 点右下角 **`创建并启用`**：
   - 新建成功 → 弹框关闭，该预设自动成为**当前生效预设**，面板列表可见；
   - 校验失败（重名、名称含空白、非法正则等）→ 弹框保留、顶部红字提示，修改后可重试。

**弹框内每个区块详解**：

### 3.1 预设名称

新预设的名字。规则：**非空、不能含空白字符（空格/Tab）、≤64 字符、不能与现有预设重名**（编辑时允许保留原名）。建议用无空格短名，如 `work`、`ci`、`restricted`（命令 `/custom-permission preset work` 也按这个名切换）。

### 3.2 自动允许的工具调用（`allowRules`）

命中下面规则的调用**不再弹审批、直接放行**（可用于自动放行你信任的命令/工具）。

每条规则一行，由**工具模式**与可选的**条件**组成：

- **工具模式输入框**（第一行）：匹配"调用的是哪个工具"。三种写法：

  | 写法 | 规则 | 示例 |
  |---|---|---|
  | 精确名 | 只有名字完全相同的工具命中（大小写敏感） | `bash`、`write`、`web_search` |
  | glob | 名字里有 `*` `?` `[` `{` 等通配符时按 glob 匹配（`*` 不跨 `/`，`**` 可跨） | `fs_*`、`{read,write}_*` |
  | 正则 | 以 `regex:` 开头，后接 JavaScript 正则 | `regex:^web_`（匹配 `web_search`、`web_fetch` 等） |

  > Windows 上的 shell 工具是 `pwsh`，macOS/Linux 是 `bash`——演示时请按你的平台填。

- **＋ 添加条件**：点它给这条规则加一行"条件"，进一步限定"**什么样的参数**才放行"。一个条件有三格：
  - **字段**：要检查的工具参数名。最常见的：shell 命令的整段文本填 `command`（匹配命令内容）；文件系统工具的目标路径填 `path`。其他工具看它的参数名（例如网页抓取类工具可试 `url`），支持 `a.b` 点路径访问嵌套参数。**参数的整个字符串**参与比较；参数缺失或不是字符串时，这条条件永远不命中。
  - **类型**（下拉框，四个选项）：

    | 类型 | 含义 | 例子：字段 `command`、值 `git` |
    |---|---|---|
    | contains | 字段值里**包含**这个子串即可 | 命令文本里任意位置出现 `git` |
    | regex | 字段值按 **JavaScript 正则**匹配（不自动锚定；要匹配整串请写 `^…$`） | `^git ` —— 以 `git ` 开头 |
    | prefix | 字段值**以**这个文本**开头** | `git status` —— 以 `git status` 开头 |
    | glob | 字段**整个值**按 glob 匹配（支持 `*` `**` `?` `[set]` `{a,b}`，`*` 不跨 `/`） | `git *` |

    > regex 类型保存时会做语法校验，写错（如 `[` 未闭合）会**保存失败并提示**，不会静默保存。
  - **值**：比较用的文本。一行留空保存时会被丢弃。
  - 条件行右侧 **✕** 删除该条件；规则行右侧 **✕** 删除整条规则。
  - **多条条件之间是 AND**（都要命中才算命中）；对同一字段也可以加多条不同类型条件（彼此 AND）。

- **＋ 添加规则**：新增一条空白规则行。**工具模式留空的规则行保存时会被丢弃**（想删一条规则，清空它的工具模式或点行尾 ✕ 都行）。

示例：放行 `pwsh` 中所有以 `git status` 开头的命令 → 工具模式 `pwsh`，＋ 条件：字段 `command`、类型 `prefix`、值 `git status`。

### 3.3 自动拒绝的工具调用（`denyRules`）

与 3.2 的填法完全相同，只是语义相反：命中即**直接失败**，工具结果里出现拒绝文案，模型能看到。

比允许规则多一个可选项——**拒绝原因**（规则行底部右侧的输入框，灰色提示"拒绝原因（可选，模型可见）"）：命中时展示给你的文案，留空则显示默认的 `blocked by dsh-custom-permission rule #N (tool "…")`。

> 同一预设里 deny 优先于 allow：即使某调用同时命中两条，也按拒绝处理。

### 3.4 自动放行审批的工具（`allowApprovals`）

每行一个**精确工具名**：该工具发起的审批请求（**包括文件系统的沙箱升级审批**）都会自动通过，不弹卡片。

- **只支持精确工具名**（如 `fetch`、`write`、`web_search`）；**不支持通配符/正则**，写了 `fs_*` 不会生效。
- 逐条添加：一行一个名字，行尾 ✕ 移除；点 **＋ 添加工具** 增加空行。
- 请只在信任的工具上开启——放行范围覆盖该工具的升级类审批（可能拿到完整访问权）。

### 3.5 额外可写路径（`extraWritableRoots`）

每行一个路径：`workspace-write` 沙箱模式下，允许文件系统工具**读写这些会话工作区之外的路径**（只影响文件系统工具，不影响 shell 的进程沙箱）。

- 建议写**绝对路径**，如 Windows `C:\Users\你\Documents\dsh-extra-test`、macOS/Linux `/home/你/data`；相对路径按后端 `cwd` 解析后规范化。
- 一行一个；行尾 ✕ 移除；**＋ 添加路径** 增加空行。
- 生效后，模型上下文里会出现这些路径"also writable"的说明，便于它正确使用。

### 3.6 保存 / 取消 / 错误提示

- **创建并启用**（新建时）/ **保存修改**（编辑时）：提交全部内容；提交中按钮显示"保存中…"并禁用。
- **取消** 或点弹框外空白：放弃本次改动关闭（已保存过的预设不受影响）。
- 保存失败时弹框内出现红字原因，常见于：名称空/含空白/重名、正则语法错误、工具模式无法编译。修改后再次保存即可。

## 4. 编辑已有预设（改规则 / 改名）

1. 面板列表里点目标预设行的 **✎**。
2. 弹框打开后**自动带入该预设当前的规则**（与 YAML/上次保存一致），字段填法与"新建"完全相同。
3. 可以：
   - 只改规则（工具模式、条件、名单等）；
   - **改名**：修改顶部的预设名称输入框。
4. 点 **保存修改**：
   - 改名生效：列表里名字变化；如果改的是**当前生效预设**，激活标记自动跟随新名字；
   - 若只是改名不动规则，直接保存即可。

---

## 5. 删除预设

1. 点目标预设行的 **🗑** → 该行按钮变成红色 **确认删除？**。
2. 再点一次确认删除（点 ✕ 取消）。
3. 守卫：**当前正在生效的预设**与**最后一个预设**不允许删除，会收到错误提示——需要时先切换到别的预设再删。

> 删除的是该预设的整套规则；切换选择与预设表都持久化，重启后保留。

---

## 6. 常见问题

- **面板/按钮不见了？** 确认 profile 装着本插件并已刷新页面；插件未加载时检查启动日志（配置错误会导致加载失败并指名原因）。
- **保存失败提示"already exists / 名称含空白 / 非法"**：见 3.1/3.2 的规则修正即可。
- **改完想立刻看到效果？** 保存/切换即生效（进程级），对**所有会话**生效，下一条工具调用即按新规则判定。
- **与配置文件（cordis.patch.yml）的关系**：未做过任何界面改动时，面板显示的是配置里的预设；一旦在界面里新建/编辑/删除过，预设表就持久化到 `settings.yaml`（`custom-permission` 命名空间）并由其接管，之后改配置文件不再自动合并（详见 README「预设切换与管理」）。想把界面里的改动清掉回到配置文件，删除 `settings.yaml` 中 `custom-permission` 段的 `presets`（重启后生效）。
- **命令入口仍可用**：`/custom-permission presets` 查看，`/custom-permission preset <名>` 切换，与面板操作互通。
